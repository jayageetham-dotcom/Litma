# Litma — notes for Claude

Malayalam literary writing app. **npm-workspaces monorepo**: `apps/web` (Next.js 15 **static export**, served at the domain root (empty basePath), React 19 + Tailwind v4 + SCSS + Tiptap 2), `apps/desktop` (Electron, macOS + Windows), `apps/mobile` (Flutter, iOS + Android), shared `packages/*`. Backend: Supabase project `jdexadomaxjtxlvgtldu`. Hosted on cPanel at **https://getlitma.in** (moved from https://www.jayageetham.com/litma, Nov 2026), deployed by `.github/workflows/deploy.yml` (FTPS to the getlitma.in FTP account: variable `LITMA_FTP_USERNAME`, secret `LITMA_FTP_PASSWORD`; the upload is skipped with a warning until both exist). The old address gets `deploy/legacy-litma/.htaccess` (301 to the same path on getlitma.in, 308 for `/mcp`) via Actions → **Redirect the old Litma address**, run once after getlitma.in is live. The desktop app, the MCP function and Supabase auth still accept the old address so apps from before the move keep working. The native phone app is being built in phases (see `apps/mobile/README.md`).

## Products in this repo (monorepo, Nov 2026)
- **Litma** (web, desktop, phone): one version, released by Actions → Release (tags `vX.Y.Z`).
- **Litma Malayalam Keyboard** (`apps/keyboard`, native Swift + Kotlin, separate store listings): its own versions (tags `keyboard-vX.Y.Z`) and checks (`keyboard.yml`); see `apps/keyboard/README.md`. Not an npm workspace, not bumped by `scripts/release.mjs`.
- Shared engine data (the Manglish word list) for any product: reusable workflow `engine-data.yml` (artifact `engine-data`).
- A new product gets its own folder under `apps/`, its own workflow with `paths:` filters, a line in `deploy.yml`'s `paths-ignore`, and its own tag prefix. Never make Litma's Release or deploy run for another product, or the other way round.

## Every change: the checklist (owner's standing rule)
Whenever anything in Litma is **added, changed or removed**, go through this list before finishing. It applies to small fixes too; skip only the lines that really don't apply.
1. **Every app:** web, desktop (Electron) and phone (Flutter), as in the section above.
2. **Strings (i18n):** new UI text goes into `packages/i18n/locales/en.json` **and** `ml.json` (same key, same `{placeholders}`, plural `_one`/`_other` in both), never inline. Changed wording: change both. Removed feature: delete its keys from both. Then `npm run mobile:assets` (the phone's copy) and `npm run i18n:check` (CI fails on a missing Malayalam string). Only the owner's admin dashboard (`admin.*`) may stay English. The sign-in pages and their error messages (`lib/auth.tsx`, phone `authMessage`) are still English inline; keep them that way until they move to i18n together.
3. **Help guide:** update the guide for the feature in `apps/web/content/help/` (README there explains the format): new feature, new guide or section; changed behaviour, change the steps and pictures; removed feature, remove its text and every link to it. Never change a live `{#id}`. Link related guides to each other, and keep each topic's `summary` true.
4. **Privacy Policy and Terms** (`app/privacy`, `app/terms`, and the community guidelines for forum changes): when data collected, a service that sees writers' data, deletion, moderation or account rules change. Update the date at the top.
5. **Credits:** new outside data, fonts, code or services go in `THIRD_PARTY_NOTICES.md` and the help section `11-account.md#credits` only (see Writing aids → Credits).
6. **Security:** a new outside host (script, API, font, frame) goes into the CSP in `apps/web/public/.htaccess`; a new Edge Function gets a `config.toml` entry, a line in `deploy.yml`, auth checks and a rate limit (`_shared/ratelimit.ts`); new email/password auth calls go through `useCaptcha` / `withCaptcha`.
7. **Setup:** a new secret, variable, migration, cron job or dashboard switch goes into `docs/setup/google-and-supabase.md` (and its checklist).
8. **Project docs:** `README.md` (features, table, layout), `apps/mobile/README.md` (what the phone has or must mirror), this file's map and rules, and `docs/changes/` (each app's file and the cross-platform summary with Open items).
9. **Checks:** `npm run typecheck`, `npm run build`, `npm run i18n:check`, `npm run sync:shared` (no drift); `flutter analyze && flutter test` in `apps/mobile` when the phone changed (or say it is unverified).
10. **Tell the owner** whether a desktop Release or a phone store build is needed for writers to get it.

## Fairness (owner's standing rule)
- Never discriminate by religion, caste, race, community, region, gender, age or ability, in anything: UI text, sample and template content, dictionary lists, quotes, examples, AI prompts, MCP text and emails.
- Treat every community the same way. Their words, festivals, food, names and customs sit side by side as equals: never in an "other" or "also" section, never as an afterthought, never labelled by community (ഉമ്മ beside അമ്മ, not under "Muslim words").
- Draw examples, sample texts, names and quotes from all of Kerala's communities, not one.
- No caste names, slurs or words that rank people. When a source (Olam, Datuk) words a definition in a dated or one-sided way, don't repeat that wording in Litma's own text.
- Before finishing content work, check it for this.

## Rules
- No Next.js server features: no API routes, middleware, server actions or dynamic route segments. One exception: `app/help/[id]` (one page per help guide), whose every page is built ahead of time (`generateStaticParams`, `dynamicParams = false`); a new dynamic segment is fine only on those terms, never one that needs a server. Use query params (`/write/?id=`, `/read/?s=`, `/book/?id=`, `/print/?doc=|book=`, `/desk/?view=books|trash`). Server work goes in `supabase/functions/*`.
- `packages/shared/src/*` (imported as `@litma/shared/<file>`) must stay dependency-free and import siblings with `.ts` extensions; `npm run sync:shared` copies it to `supabase/functions/_shared` (CI fails if they drift). The web build runs it.
- Workspace packages ship TypeScript source; `apps/web/next.config.ts` lists them in `transpilePackages`.
- Design tokens: edit `apps/web/src/styles/theme.css`, then `npm run tokens` to refresh `packages/tokens/tokens.json` (CI checks it) for the native apps.
- Paths below under `src/` mean `apps/web/src/`.
- Links: `next/link` handles the base path; raw `<a href>`/`window.location` need `BASE` / `appUrl()` from `src/lib/config.ts`.
- New tables: enable RLS with `(select auth.uid())` ownership policies, `to authenticated`, and run Supabase advisors.
- Never store raw MCP tokens — only SHA-256 hashes (`mcp_tokens.token_hash`). AI keys are per writer, AES-GCM encrypted in `ai_keys` (no RLS policies; only the `litma-ai` function touches them). No server-wide AI keys.
- New documents carry `settings.pristine = true` until the writer types; pristine docs are deleted on close and by the desk's cleanup. Story World cards closed without content are deleted too (`isBlankItem` in `src/lib/story.ts`).
- Don't change other users' data with SQL without asking the owner.

## Editor behaviour (keep these working)
- Pages flow naturally (Google Docs style): `extensions/pagination.ts` measures top-level blocks and inserts spacer decorations; breaks live in `paginationKey` state (`breaks[i].pos` = first block of page i+2). A page exists only while text reaches it, so deleting the last character of a page removes it.
- **Insert page** is the only way to force a page: the "+ Insert page" button in the gap between two sheets (always visible on touch) calls `insertPageAt(pos)`, adding `[pageBreak] [empty paragraph] [pageBreak]`. The `pageBreak` node is invisible and not selectable (no dashed line, no label, no toolbar button, no Ctrl+Enter: the owner found the visible component annoying). Backspace at the start of a page removes the break before it; on an empty inserted page it removes the whole page; Delete at a line end removes a following break. Don't add delete buttons for pages.
- Body text of every writing type is ragged-right (`text-align: start`) like Google Docs, in the editor and the PDF/book output, so short Malayalam lines never open wide word gaps (the owner asked twice). Justify only when the writer picks it on the toolbar. Indent/alignment rules use `> p:not(.sb)` so styled blocks (title, standfirst…) never inherit them. Novels and stories indent body paragraphs 1.6em like a printed book, except the first of the work, the first after a heading or break, and around an empty line: an empty line is a section break (it and the next paragraph sit at the margin; owner's choice, Nov 2026). Same rule in `editor.scss` (`.is-empty`, `:empty`), Word export (`export.ts`) and the phone app (`block_style.dart`).
- Reader view for shared links (`app/read`, `/read/?s=`): the title and the writer's byline (pen name or name and avatar, from the `shared_author(share_id)` function, since visitors can't read profiles; falls back to the work's own author block), then the work on its printed pages via `paginate` + `documentPrint` (same as its PDF). Pages with no text are removed and the rest renumbered 1, 2, 3 (owner, Nov 2026); pages shrink to the screen width (`zoom`). Outline beside them on wide screens, reading progress, one Close in the header. HTML for reading, books and print comes from `renderDocHtml` (`lib/doc-html.ts`), which adds the editor's `own-first-colour` class that plugins can't add in generateHTML.
- Novel/story drop cap (first akshara after a chapter) is a real `<span class="drop-cap">` from a decoration in `FirstLetterColour` (extensions/blocks.ts) and `renderDocHtml`, never CSS `::first-letter`: that made Chrome drop the cursor after the first letter (a space or comma after a Manglish word landed inside the word), painted selections partly and cut conjuncts. It takes a whole syllable (`firstAksharaLength` in `shared/akshara.ts`, `lib/core/akshara.dart` in the phone app) so സ്നേ stays shaped. Accent colour only when the paragraph doesn't start with the writer's own colour (`.own-first-colour`).
- Suggestion lists keep focus in the text and act like a combobox: keys in the editor (`useSpellKeys` in `SpellSuggest.tsx`: ↓/↑, Enter, Esc, Alt+↓; Manglish keys in `extensions/manglish.ts`), the editor's `aria-activedescendant`/`aria-controls` set only through `ownAttr` (`components/editor/aria-owner.ts`, prefix per list so they never clear each other), option ids, `lang="ml"` on Malayalam options and an always-mounted polite live region. Phone rows (`lib/editor/suggestion_rows.dart`): one `Semantics(container, button)` per chip with a Malayalam `attributedLabel`, Ignore/Keep named by their word with the hint as hint; checked by `test/suggestion_rows_test.dart`.
- Right-click menu (Nov 2026, web + desktop, pointer devices only): `components/editor/EditorContextMenu.tsx`, mounted in Workspace when not on a phone. Spelling fixes for a marked word first (`issueAt`), then Cut/Copy (`execCommand`), Paste / Paste without formatting (desktop: `litmaDesktop.edit` → `webContents.paste`/`pasteAndMatchStyle` in `main.ts`; browser: `navigator.clipboard` → `view.pasteHTML`/`pasteText`, a toast with the shortcut if blocked), Delete, Select all, Look up / Rhymes / Ask AI (select the word under the pointer first), B/I/U, Clear formatting, Shortcuts. Focus stays in the text (window keydown in capture: ↑↓ Home End Enter Esc; `aria-activedescendant` via `ownAttr` with prefix `ctx-`). It fires `CONTEXT_MENU_EVENT` so `SpellSuggest` hides while open. Shift + right-click keeps the browser's menu. Outside the editor the desktop app shows a small native Cut/Copy/Paste menu (`editMenuFor`). Placement: below the clicked line, else above, else the roomier side with its own scroll; it never covers the line (one layout read per opening).
- Suggestion buttons cancel `pointerdown`/`mousedown` (keeps the editor focused) and act in `onClick`: with `pointerdown` cancelled Chrome never sends `mousedown`, so a pick there never ran.
- Text colour and highlight are two tools (`components/editor/ColorTools.tsx`): swatches, a custom colour picker with recent colours, "Automatic" / "None". Text swatches are fresh tones that each keep ≥ 4.5:1 on white paper. Coloured spans carry the colour as `--tc` with class `.tc` (Color extension in `extensions.ts`), so dark mode can show them lighter (OKLCH lightness ≥ 0.78) without changing the stored colour; highlighted text turns dark in dark mode.
- `extensions/keep-selection.ts` keeps the selection when the editor blurs (phones collapse it when the keyboard closes) and shows it as `.kept-selection`. ## നാട്ടറിവ് (Dictionary tab, owner's rules)
- Categories of Malayalam words with English meanings, shown in the Dictionary as Look up · നാട്ടറിവ് · Saved. Data: `packages/shared/src/nattarivu.ts` (plain data, synced to `supabase/functions/_shared`; the mobile app ports it). UI: `components/Nattarivu.tsx`. URLs: `/dictionary/?view=nattarivu&c=<id>`; a word opens as `?w=<word>&from=<id>` with a chip back to its category.
- **Only words that have a dictionary entry whose meaning matches.** Never add a word without an entry, and drop a word whose entry means something else (ചമ്പ is dried fish, not the tala; ബുധൻ is not Wednesday, so the weekdays use ബുധനാഴ്ച). Check every word against the built `apps/web/public/dict` data (build it with `node scripts/build-dictionary.mjs --cache .dict-cache`) and read Datuk's definitions for the less common ones.
- Words that belong to Malayalam and Kerala. Leave out vocabulary shared across South Indian languages as a technical list (no ragas or Carnatic talas; Kerala-specific ones like ചെമ്പട, പഞ്ചാരി, സോപാനം are fine).
- Cover all of Kerala's communities evenly (Hindu, Muslim, Christian and others): festivals, food, dress, ornaments, arts, music and the words families use. Customs and festivals are fine; prayers, rituals and deities are not. No occupation words that double as caste names. Many Mappila and Christian words (ദഫ്മുട്ട്, മാർഗംകളി, നെയ്ച്ചോറ്, വട്ടയപ്പം…) are missing from Olam, and ഒപ്പന is there only as "agreement", so they can't be added until the dictionary has them.
- Familiar-first order, not alphabetical. English is a plain meaning; named art forms and instruments get a short description ("Kathakali, classical dance-drama").
- Sections: a line `# മലയാളം | English` starts one. Use sections when a category splits naturally (കല: art forms, instruments, folk games, festivals, music); no one-word sections; small related categories are merged into one with sections (കാലം holds seasons, months, birth stars, times of day, weekdays).
- Words from different communities for the same thing sit together as equals (ഉമ്മ and അമ്മച്ചി beside അമ്മ, ഇക്ക beside ചേട്ടൻ), never in a separate "other" section.
- Short category names (ഉപകരണങ്ങൾ, not നാടൻ ഉപകരണങ്ങൾ; ഭൂപ്രദേശം for terrain). Keep a word in one category. When a category is merged or renamed, keep its old id working in `MOVED`.
- Each category card shows a lucide icon in a soft tile of its tint (`ICONS` in `components/Nattarivu.tsx`, keyed by category id); a new category needs an icon there too.
- Card titles stay on one line inside their card (long single words shrink to fit; on phones such a card spans the row).

## Writing aids (Nov 2026: free features, every app)
- **Rhymes (പ്രാസം):** `packages/shared/src/rhyme.ts` (`rhymeKey`, `rankRhymes`, `rhymeSource`, `createRhymes`; phone `lib/data/rhyme.dart`). - **Metre (വൃത്തം, Nov 2026):** `packages/shared/src/metre.ts` (`scanLine`, `readings`, `checkStanza`; phone `lib/core/metre_check.dart`, same answers checked by `test/metre_test.dart` against `test/metre_vectors.json`, which `npm run mobile:assets` writes from `test/metre_inputs.txt`). Rules from Vrittamanjari (1904): a word-final ് is read both ways (short syllable, or not counted with the syllable before it guru), a line's last syllable is free. Sanskrit metres (`SAMA`, `ARDHASAMA`, `UPAJATI`, അനുഷ്ടുപ്പ്) are named only when every line fits ("exact") or "close" (at most two syllables off a line, half the lines fit); Malayalam metres (`BHASHA`: കേക, കാകളി, മഞ്ജരി, നതോന്നത, അന്നനട, തരംഗിണി…) are "likely" from the aksharas per pair of lines and the gana shapes, "close" only with three lines or more. Free verse gets "none", never an error. Only metres whose definition two sources agree on (കുസുമമഞ്ജരി left out). - **Spelling:** `packages/shared/src/spell.ts` (phone `lib/data/spell.dart`, same cases in `test/spell_test.dart`): broken Unicode (old chillu, split vowel signs, stray joiners, colon for ഃ), `MISTAKES` (only misspellings the dictionary itself doesn't list; inflected forms marked only when unknown), and optional "not in the dictionary" (a question, never an error: dialect and community words are often missing). ## Offline (web and desktop)
- Both apps work with no connection. `src/lib/offline.ts`: an IndexedDB copy of the writer's works (with text), books, Story World, recent versions, profile, saved words (per account), and an **outbox** of changes made offline, merged per row and sent in order on `online`, app start and every 30 s while anything waits (`startSync()`, started by `components/OfflineStatus.tsx`).
- `store.ts` (cloud mode) goes through `cloudRead` (server after sending the outbox, else the device copy) and `cloudWrite` (send now, else queue; `updateDoc` resolves true when queued). New rows get their id on the device (`uuid()`), so later offline changes can refer to them. Queries go through `remote()`, which turns network failures into `OfflineError` and marks the server unreachable (wifi without internet, server down) so later calls use the device copy at once; the sync loop probes until it answers. New store methods must follow the same pattern.
- Conflicts: offline text saved over a work changed elsewhere first keeps the server's text as a version "Before offline changes" (`_content_at` = the server time the device's text is based on).
- Auth: an expired session can't refresh offline; `useUser` keeps the writer remembered on this device (`litma:offline-user`, cleared on sign-out) instead of sending them to sign in.
- UI: the editor's save line shows "Offline. Safe on this device…" (status `local`) until the outbox is sent; `OfflineStatus` shows a small pill (offline / sending / all synced; strings `offline.*`). A work never opened on this device shows "Not on this device yet" offline. Recently changed works are prefetched with their text after each desk listing.
- Website: `scripts/write-sw.mjs` writes `out/sw.js` after the build (every page, RSC payload and `_next/static` file precached per build; pages network-first with a 4 s fallback to the cache; dictionary, pictures and Google Fonts kept when used; Supabase never touched). `components/ServiceWorker.tsx` registers it on the website only.
- Desktop: `/dict/*` and Google Fonts (`/gfonts/`, `/gstatic/` in the desktop build) are kept on disk by `kept()` in `apps/desktop/src/main.ts`.
- Test without real Supabase: a small mock (auth + PostgREST in memory) with `NEXT_PUBLIC_SUPABASE_URL=http://localhost:<port>`, then Playwright `context.setOffline(true)` or stopping the mock.

## Design system
- **All tokens live in `src/styles/theme.css`** (light in `:root`, dark in `.dark`): canvas · surface · subtle · paper · header · ink · muted · line · primary · accent (violet, from the home page) · highlight (amber) · tint-* (violet, coral, sky, lime, tangerine) · danger, option-hover/selected, demo-*, plus radius, shadows, fonts and the solid `--brand` / `--brand-mark`. Edit there to restyle the app.
- Contrast: text tokens meet WCAG AA (muted ≥ 6:1, highlight ≥ 4.5:1 on its soft background); `--line` is for decorative dividers, `--line-strong` (≥ 3:1) for field, select and outline-button edges. Disabled filled buttons use `--disabled-bg/-ink`, not opacity. Danger buttons: `.btn-danger`.
- Use the generated classes (`bg-surface`, `text-accent`, `bg-primary text-primary-ink`, `text-highlight`…); never hard-code colours in components. Buttons: `.btn` + `btn-primary` (ink-black) / `btn-accent` (indigo) / `btn-outline` / `btn-ghost`. Top bars: `.app-bar` (sticky, translucent) or `bg-header`.
- Inside the app the home page's freshness shows only lightly, so writers keep their focus: a faint lilac canvas, the violet accent, `tint-*` colours on tool icons (each editor rail tool and phone "More" tile has its own, via `tint`) and a small dot per writing type on desk cards (`kindDot` in `src/lib/tints.ts`, same order as the home page). Never tint text, the page or large surfaces in the app.
- App chrome stays calm: the logo is solid ink `ലിറ്റ്മ` with an indigo dot (`.brand-text`), thin accent lines `.brand-bar`, no gradients in the app (the owner rejected Instagram-like ones there).
- The home page is the exception: it uses the colourful landing palette (`--mist`, `--night`, `--violet`, `--coral`, `--lime`, `--sky`, `--tangerine`, `--on-pop` for text on bright fills, `--violet-text`/`--coral-text` for AA text), soft blurred colour fields, and the lime→sky→violet gradient on the footer line. The owner approved these gradients. `.on-night` re-maps ink/muted/line for dark bands; Latin text there uses `--font-landing` (Manrope).
- The document page uses `--paper` so writing stays black on white; colour belongs to the chrome, not the text. Page thumbnails (`.tpl-preview`) are ragged-right so tiny justified lines don't look gappy.

## Auth emails
