# Litma for iOS and Android (Flutter)

**Store setup (owner):** Play Console app `in.getlitma.litma` and an upload keystore; App Store Connect app with the same bundle id and an API key; then add the secrets listed in `.github/workflows/mobile-release.yml` and fill the `mobile` block (store links) in `latest.json`.

A native app, not the website in a frame: the same account, works and writing types as the web and
desktop apps, with Litma's look, native gestures and transitions, and full offline use.

## Run it

Needs Flutter (stable) and, for iOS, a Mac with Xcode.

```sh
cd apps/mobile
flutter pub get
flutter run                 # on a connected phone or a simulator
flutter analyze && flutter test
```

It talks to the same Supabase project as the website (the public key is built in; override with
`--dart-define=SUPABASE_URL=… --dart-define=SUPABASE_ANON_KEY=…`).

Design previews of every screen (light, dark, phone, tablet) as PNG files in `test/screenshots/out/`:

```sh
SCREENSHOTS=1 flutter test test/screenshots --update-goldens
```

## One-time setup (owner)

1. **Supabase → Authentication → URL Configuration → Redirect URLs:** add `in.getlitma.app://auth-callback`
   (Google sign-in and email links return to the app through it).
2. **Sign in with Apple** (App Store rule once Google sign-in is offered): in the Apple Developer account,
   enable *Sign in with Apple* for the bundle id `in.getlitma.litma`; in Supabase → Authentication →
   Providers → Apple, add `in.getlitma.litma` to the client IDs. The app uses the native Apple sheet and
   sends Apple's token to Supabase.
3. **Signing:** set the Apple team in Xcode (`ios/Runner.xcworkspace`) and an Android upload key
   (`android/key.properties`) before store builds.

## How it is built

| Part | Where |
|---|---|
| Colours, radii | `lib/core/tokens.g.dart`, generated from `apps/web/src/styles/theme.css` → `packages/tokens/tokens.json` by `npm run mobile:assets` (CI checks it) |
| Strings (English, മലയാളം) | `packages/i18n/locales/*.json`, copied to `assets/i18n/` by the same script; `context.t('desk.newWork')`, same keys and plural rules as the web. App-only strings live under `app.*` |
| Theme, fonts | `lib/core/theme.dart`; Inter, Anek Malayalam, Noto Serif/Sans Malayalam, Manjari, Gayathri bundled in `assets/fonts/` (SIL OFL) |
| Motion | `lib/core/motion.dart`: one set of durations and curves, `Pressable` (press feedback + haptics), `FadeSlideIn` (staggered entrances), `Shimmer` (skeletons), `SwapFade`; all honour the system "reduce motion" setting |
| Data | `lib/data/store.dart` (same operations and rules as the web's `store.ts`), `offline.dart` (copy on the phone in SQLite + outbox, same design as the web's `lib/offline.ts`), `backend.dart` (Supabase), `auth.dart` (email, Google, Apple; stays signed in offline) |
| Writing types | `lib/data/forms.dart`, a port of `packages/shared/src/forms.ts` |
| Manglish | `lib/core/manglish.dart`, a port of `packages/shared/src/manglish.ts`; `test/manglish_vectors.json` holds the web engine's answers (regenerated by `npm run mobile:assets`) and the tests compare |
| Editor | `lib/editor/`: `document.dart` reads and writes the same Tiptap JSON as the web (nothing is dropped; parts it can't edit yet are kept as they are), `block_controller.dart` (one text field per line, marks per character, Manglish at word boundaries), `session.dart` (Enter, Backspace, formatting, undo, the template's next empty line), `block_style.dart` (the web's editor.scss rules), `saver.dart` (the web's autosave: journal, debounce, retry) |
| Screens | `lib/features/`: welcome and sign-in, desk, writing-type picker, reader, settings; `lib/editor/editor_screen.dart` |

Navigation keeps each platform's own behaviour (iOS edge swipe back, Android predictive back); a desk
card grows into the editor (container transform), the reader rises in, the sign-in gate fades through.

## What the app does (all five phases)

- **Phase 1, writing:** sign in (email, Google, Apple), desk (works, books, trash, search, swipe to trash with undo, duplicate, stats and streak), writing-type picker with live template previews, editor (every writing type's template lines and prompts, Manglish / മലയാളം / English typing with suggestions and Keep English, line styles, bold, italic, underline, strikethrough, alignment, dialogue for screenplays and plays, undo and redo, autosave, offline), reader, settings, profile (details, statistics, 20-week heatmap, edit with the avatar pictures, password).
- **Phase 2, words and worlds:** dictionary (Look up with Manglish, meanings, translations, ranked synonyms; the website's /dict data, kept on the phone once used), നാട്ടറിവ് (all categories from packages/shared, with sections and a filter), saved words; Story World per work (each writing type's sections, card editor with the web's fields, plot board with columns, timeline, report).
- **Phase 3, books and sharing:** Books tab, new books with the standard pages and the classic cover, book details, contents (add works as chapters, drag to reorder, swipe to remove), read the whole book; share a public reading link; export PDF (system print sheet, Malayalam shaped by the phone's web engine), Word (.doc) and text.
- **Phase 4, AI:** AI companion (the web's actions, ask in your own words, streamed answers with the writer's own key, insert or replace), the hand-over to the Claude app when there is no key or credit, the Assistant inbox (apply or dismiss suggestions sent through MCP), AI keys and AI-assistant connections in Settings, version history with restore.
- **Phase 5, release:** `.github/workflows/mobile-release.yml` builds the Android App Bundle (Play Console internal track) and the iOS build (TestFlight) when the store secrets exist (listed at the top of the file), and the Release workflow runs it; Android release signing from `android/key.properties`; the in-app update card and the required-update screen read the `mobile` block of `latest.json`.
- **Still to come (smaller):** text colour and highlight, font size, editing footnotes, screenplay scene tools, page view in the editor, the full cover designer with artwork (the web's), selection across lines.

## Versions and updates (plan for the Flutter app)

Litma uses **one version number** for the website, the desktop app and the mobile app (root `package.json`, bumped by the Release workflow; see the main README). For the Flutter app:

1. **Version**: `pubspec.yaml` `version: X.Y.Z+N` takes X.Y.Z from the release and N from the CI run number (stores need a growing build number). The Release workflow will gain a `mobile` job that sets it and builds.
2. **Store updates**: releases go to TestFlight / App Store and the Play Console through CI (Fastlane or `flutter build ipa` + App Store Connect API key, `flutter build appbundle` + Play service account). Phones update from the stores as usual.
3. **In-app prompt**: on launch the app reads `https://getlitma.in/downloads/latest.json`. The `mobile` block (`version`, `minimumVersion`, `ios`, `android` store links) is already in the file (filled in once the app ships):
   - newer `version` → a gentle "Update available" card linking to the store (Android can use Play's in-app updates)
   - `minimumVersion` above the installed one → a blocking "Please update" screen (for backend changes old apps can't handle)
4. **Instant fixes without a store review (optional)**: Shorebird code push can patch Dart code between store releases.
5. **Content never waits for an app update**: documents, Story World, the dictionary and AI all come from Supabase and the website, so most improvements reach phones without a new build.

## Changes to mirror in the native app
Behaviour fixed on the web that the Flutter app must match (the editor, offline, typing, sign-in and desk items are in phase 1; the rest arrive with their phase):
- **Sign in / Create account / Forgot password:** the main button stays active (it greys out only while working). Read the field values when it's pressed, so values filled in by the system's password autofill always count, and show a plain message for an empty field ("Enter your email address.", "Enter your password."). Don't disable the button just because a field looks empty.
- **Update prompt:** show it only when `latest.json` (`mobile.version`) is newer than the installed app, never on a timer by itself, and never on public screens (welcome, sign in, sign up).
- **Offline (Nov 2026):** the app must open and keep working with no connection, like the web and desktop apps (`apps/web/src/lib/offline.ts`):
  - Keep a copy of the writer's works (with their text), books, Story World items, recent versions, profile and saved words on the device, refreshed whenever the server answers. Keep the text of recently changed works even if they were never opened.
  - Offline, save every change to the device and to an **outbox** (insert / update / upsert / delete / `add_words_today`), merged per row; send it in order when the connection returns (on reconnect, on app start, every 30 s while anything waits). Give rows made offline a v4 UUID on the device; a duplicate-key answer (23505) to an insert means it already arrived.
  - Treat "server not answering" like no network (an expired session refreshing against an unreachable server can hang for 30 s: give up after a couple of seconds and use the device copy).
  - Before sending offline text over a work, compare the server's `updated_at` with the one the device's text was based on; if the server's is newer, save the server's text as a version labelled "Before offline changes" first.
  - Stay signed in offline even when the access token has expired (remember the last signed-in writer; forget them only on sign-out).
  - Show the same messages (`offline.*` in `packages/i18n`): a small "Offline. Your writing is saved on this device." note with the count of waiting changes, "Back online. Sending your changes…", "All changes synced", and "Not on this device yet" for a work that was never on the device. The save line reads "Offline. Safe on this device, will sync when back online" while changes wait.
  - Keep dictionary data and fonts on the device once loaded.
- **Session storage:** keep the Supabase session in the app's own persistent storage (supabase_flutter's default), never in web cookies. The desktop app lost every sign-in when the session lived in cookies.
- **Dictionary:** use the same data files (`/dict`), which list a word's English translations and meanings most-likely first (കവി → poet). Show translations without the source's homograph numbers ("wind-1" → "wind").
- **നാട്ടറിവ് (Dictionary):** categories of Malayalam words with English meanings come from `packages/shared/src/nattarivu.ts` (plain data). Show the category grid, a category's word list with a filter, and open a word in the dictionary with a way back to its category.
- **No photo uploads (for now):** to keep storage costs down there is no profile photo, cover picture, author photo or Story World picture upload (`PHOTO_UPLOADS = false` in `apps/web/src/lib/config.ts`). Pictures uploaded earlier still show.
  - **Avatar:** the writer picks one of the avatar pictures in `apps/web/public/avatars/` (`avatar-f-<n>.svg`, `avatar-m-<n>.svg`; bundle them as assets, ids and display order in `avatars.json`, shown alternating as equals with no gender labels) or their first letter (a whole Malayalam akshara, ക്ഷ not ക) in one of the five `tint-*` colours. Saved in `profiles.preferences` as `avatar` (`"letter"` or a picture id like `"f-1"`) and `avatarTint`. Any other id shows the first letter. A writer who never picked one gets the letter in a colour chosen steadily from their name (`tintFor`).
  - **Book covers:** `cover.art` names one of eight genre backgrounds served from the website at `/covers/<id>.svg` (fantasy, thriller, romance, scifi, horror, literary, historical, selfhelp; ids from the first version are mapped in `MOVED` in `apps/web/src/components/art/CoverArt.tsx`, which also lists each one's text and accent colours). The "Artwork" template (`template: "art"`) fills the cover with it (title at the top, author at the bottom); other templates show it in their picture slot; the back cover repeats it mirrored under a 62% scrim of the cover colour. `cover.authorAvatar` is the back-cover author picture: `"letter"` (default), an avatar picture id or `"none"`.
- **Cover designer:** match the web's `CoverFront`/`CoverBack` (`apps/web/src/components/book/Cover.tsx`): background fills every design; title shadow and box (`titleShadow`, `titleBox`, `titleBoxColor`, `titleBoxOpacity`); divider `ornament` (line, flourish, none); `badge`/`badgeText` (defaults to the edition); `publisherMark`; dragged positions in `cover.offsets` (millimetres, per part id: title, author, badge, mark, back-head, back-text, back-imprint); back-cover `backTitle`, imprint strip (`imprintStrip`, default on; publisher defaults to "Litma Publishing House") fields (`genreLine`, `category`, `coverCredit`, `publisherTagline`, `website`, price) and an EAN-13 barcode from the ISBN. Bundle the SMC title fonts from `apps/web/public/fonts/smc`.
- **Cover presets and sample values:** offer the same ten presets (`COVER_PRESETS` in `apps/web/src/components/book/Cover.tsx`, applied with `presetPatch`, which clears positions and sizes) as live previews; per-part sizes are `cover.sizes` (title uses `titleScale`). Fill never-set book fields with the samples in `apps/web/src/lib/book-samples.ts`.

- **Book details fields:** Title, Subtitle and Author accept Malayalam, English or Manglish with a മലയാളം / As typed switch per field (see `toMalayalam` in `apps/web/src/components/ScriptField.tsx`: Name-cased words read all small; capitals with no meaning in the scheme are lowered). Cover layouts and the separate Frame option as in `Cover.tsx`.
- **Writing types (Nov 2026):** starter content and settings come from `packages/shared/src/forms.ts` (`starterContent`, `newSettings` for new works; new screenplays get `headingLabels: "ml"`). Match the web editor:
  - **Enter on a template line** (title, author, chapter, scene time…) moves to the next empty line the template left, stepping over a filled label like പല്ലവി or കഥാപാത്രങ്ങൾ; only when there is none does it add body text (`moveToNextSlot` in `apps/web/src/extensions/blocks.ts`).
  - **Prompts** sit where the text goes (centred on centred lines). Author prompt is "എഴുതുന്ന ആളുടെ പേര്" and the block is "രചന · Author" (no gendered wording).
  - **New blocks** (`styledBlock` variants): `stanza` (poems, numbered), `act` and `scene` (plays, numbered; scene numbers restart in each act), `refrain` (songs, starts with the first words of the പല്ലവി), `credits` (song details), `infobox` (features), `references` (essays). Show menus and buttons in both languages ("അങ്കം · Act", "രംഗം · Scene").
  - **Plays:** cast list as `castEntry` (`castName` + `castRole`) nodes, filled from Story World characters; stage direction button; Tab after speech adds a stage direction; Enter on an empty speaker line becomes a stage direction.
  - **Screenplays:** Enter on the empty line after the last cast name goes on to the action; scene tools set Int./Ext. and the time and fill the cast from the scene's speakers; scene numbers read "രംഗം 1", "Scene 1" or the older "Scene: 1" (`settings.headingLabels`).
  - **Footnotes** (essays, features): inline `footnote` node with `attrs.text`, numbered in order and listed at the end ("കുറിപ്പുകൾ") on screen, in print and in Word.
  - **Diary:** "New entry" adds today's date heading at the end (`todayLine()`), or goes to the end if today's entry exists.
  - **Settings:** `chapterNumbers` (novel/story), `headingLabels` (screenplay/drama), `verseAlign` (poem/lyrics). Layout classes as in `docClasses()` (`apps/web/src/lib/templates.ts`).
  - **Phones** show the writing at full size on one continuous sheet (no A4 page shrunk to the screen); a "Pages" switch shows the printed pages.
  - Strings: `editor.drama.*`, `editor.scene.*`, `editor.diary.*`, `editor.footnote.*`, `editor.page.*`, `types.<kind>.blurb`, `story.tabs.*` in `packages/i18n`.
- **നാട്ടറിവ് icons:** each category card shows an icon in a soft tile of its tint; the web uses lucide icons keyed by category id (`ICONS` in `apps/web/src/components/Nattarivu.tsx`). The Flutter app can use the same names from the `lucide_icons` package.

## Usage statistics (mirror the web app)

Send the same events as `apps/web/src/lib/analytics.ts` to the `litma-track` Edge Function (POST JSON `{ vid, sid, ctx, events }`, the writer's access token as Bearer), with `ctx.platform` = `android` or `ios`: `page_view` per screen (route path only), `click` with a label only from the app's own strings, `work_created`, `book_created`, `export`, `dictionary_lookup`, `sign_in`, `sign_up`, and `engagement` (`{ seconds }`). Honour the Settings switch. Never send writing, titles, names or search words.
